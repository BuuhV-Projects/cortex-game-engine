## Decided
2026-09-25: no host nativo o passe de sombra redesenhava ~140 malhas fundidas por quadro
(sol cobre o mapa, merged atravessa o mapa → todas no shadow map). `mergeStaticScene` agora
cria `static-shadow-proxy` (FrontSide) e `static-shadow-proxy-double` (DoubleSide): só
posições+índice, layer `SHADOW_PROXY_LAYER` 29; malhas por material ficam `castShadow=false`.
Medido (release 720p): 287→138 draws, JS 17,3→11,3 ms, sombra IDÊNTICA (diff de pixel 0%,
controle sem sombra = 18,4%), carga +0,9 s, external +65 MB. Commits f0bb687c/25689942.

**Why:** 1ª versão só aceitava FrontSide e criou ZERO instâncias — os 116 materiais do kit
do crash vêm `doubleSided` do Blender (backface culling off por padrão). Só o log
`?cortexDebug=scene` ("sombra única: N instâncias") revelou; draws iguais foram a pista.

## Watch out
conferir `shadowProxyParts` > 0 no log antes de medir fps. Medir release:
`CORTEX_FRAME_TIMING=1 CORTEX_VRAM_LOG=1` → perf-log (`js med`); debug do engine no nativo via
`CORTEX_LAUNCH_QUERY='?cortexDebug=scene,boot'`. Monitor do usuário: 1080p 75 Hz (vsync Fifo)
→ meta 13,3 ms; `maxFps` só divisor do refresh (crash foi pra `maxFps=0`, SPEC-0003 do jogo).
Ver oom-hermes-fusao-estatica, validar-instrumento-antes-de-concluir.
